# Waffle Character Asset System Design

## Summary

Create a durable visual identity for Waffle, the project's orange-tabby mascot. The system will have two coordinated tiers:

- **Hero Waffle:** a richer, more illustrative treatment for landing pages, announcements, and large editorial artwork.
- **Motion Waffle:** a simpler layered vector character for documentation poses, interactive web animation, and promotional video.

Both tiers derive from one approved character canon and layered vector source of truth. Generated images may be used to explore directions, but production assets must be reconstructed, reviewed, and exported from the vector master.

## Goals

- Make Waffle recognizably based on the real cat rather than a generic orange tabby.
- Produce consistent, editable SVG poses for future documentation.
- Prepare the character structure for reusable layered-SVG animation.
- Support later raster, interactive web, and promotional-video outputs without redrawing the identity from scratch.
- Preserve provenance while keeping personal reference photographs out of Git.

## Non-goals

- Building the documentation site.
- Completing the polished hero recreation.
- Creating the documentation animation runtime or promotional videos.
- Choosing the documentation site's framework or visual design.
- Generating a large pose library before the character canon is approved.

## Provenance and Rights

The seed illustration was generated by the project owner using the ChatGPT web client. OpenAI's current individual Terms of Use state that, as between the user and OpenAI and to the extent permitted by law, the user owns the output; they also note that outputs may not be unique. Retain the original file and a provenance note in the private working archive. Do not represent the generated seed as human-drawn.

Real-cat references were supplied through a private iCloud share containing 11 photos and 3 videos. Do not commit the photos, videos, expiring share URL, or identifying metadata. The repository may record that owner-supplied private references were reviewed and the date of review.

## Character Canon

Waffle is an **eternal kitten** and remains **cat first**. Her default anatomy, locomotion, balance, and resting poses should read as feline. She may briefly stand on two legs, wave, point with a paw, hold a small object, peek around a panel, or interact with interface elements, but she must not become a permanently upright human-shaped character.

Identity anchors derived from the references are:

- warm ginger coat with darker classic-tabby swirls;
- strong forehead M and cheek stripes;
- pale muzzle, chin, eye surrounds, and belly;
- grey-green eyes and a pink nose;
- large ears and long whiskers;
- banded legs and a distinctly ringed tail;
- long, slightly lanky kitten proportions; and
- a curious, affectionate, mischievous "little princess" personality.

Every approved pose must preserve the forehead M, eye colour, pale muzzle, leg bands, flank swirls, ringed tail, and kitten proportions. Shading and fur detail may vary by tier; identity anchors may not.

## Asset Architecture

The system has three upstream layers:

1. **Private reference archive:** original generated illustration, real-cat media, and provenance.
2. **Character model sheet:** canonical proportions, markings, palette, expressions, and do/don't rules.
3. **Layered vector master:** named, editable shapes for anatomy, facial features, markings, and shading.

The vector master feeds both Hero Waffle and Motion Waffle. Motion Waffle then supplies standalone SVG poses and, in a later phase, code-driven animation of the same named SVG groups. Downstream exports may include optimized SVG, transparent PNG/WebP, MP4, WebM, GIF, or image sequences.

The vector master is the production source of truth. AI-generated concepts, raster traces, optimized exports, and rendered video frames are derivatives and must never overwrite it.

## First Production Milestone

The first milestone delivers:

1. A character-canon document with palette, proportions, markings, personality, and do/don't examples.
2. A model sheet with front, three-quarter, profile, and rear/top marking views.
3. An expression sheet covering neutral, curious, pleased, focused, startled, and sleepy states.
4. Three Motion Waffle poses: neutral standing, sitting, and curled/resting.
5. A named, layered vector source suitable for clean SVG export and later animation.
6. Standalone SVG exports and transparent PNG previews.
7. A QA contact sheet comparing the character against the private references and seed illustration.

The hero recreation and animation implementation begin only after this milestone is accepted.

## Production Workflow

### 1. Concept exploration

Use the approved references to create rough pose, expression, silhouette, and simplification studies. Generation may accelerate this stage, but all outputs are disposable proposals.

### 2. Vector reconstruction

Build the chosen direction in editable, SVG-compatible layers. Establish silhouette and anatomy before facial features, markings, colour, and shading. Use a restrained number of paths and gradients so Motion Waffle remains legible and efficient.

The source format must remain tool-neutral at the repository boundary. Illustrator, Affinity Designer, Inkscape, or another editor may be used, but a clean layered SVG representation is required.

### 3. Incremental review gates

Review and approve these independently:

1. silhouette and proportions;
2. face and expression language;
3. marking placement and palette;
4. model-sheet views; and
5. final static poses.

A rejected gate returns only to the affected layer or stage.

### 4. Export and validation

Export standalone SVG and transparent PNG previews. Validate consistent view boxes, transparency, small-size readability, browser rendering, SVG structure, and visual parity with the approved source.

### 5. Animation preparation

Keep the head, ears, eyes, eyelids, muzzle/mouth, torso, limbs, paws, and tail separable. Establish useful pivots and avoid baked overlaps that prevent natural joint movement. The first layered-SVG prototype should use the browser's Web Animations API, with Motion as an optional ergonomic wrapper, and test only idle breathing, blinking, ear movement, and tail movement before more complex actions.

Do not store personal cat media under this tree. Large proprietary editor files should not become required build inputs. If later binary animation or video sources grow materially, evaluate Git LFS before committing them.

## Quality Gates and Acceptance Criteria

The first milestone is accepted when:

- all canonical views and expressions read as the same kitten;
- the identity anchors match the reference-derived canon;
- each pose reads clearly at both documentation and hero-preview sizes;
- no pose appears permanently humanoid;
- SVGs contain editable, logically named groups rather than a flattened embedded bitmap;
- SVGs render consistently in current Chromium, Firefox, and Safari engines;
- transparent PNG previews have clean edges and no matte fringe;
- the motion master has separable parts and plausible pivots for the planned layered-SVG prototype; and
- the QA sheet records approval or a specific revision request for every deliverable.

Reject work that shows marking drift, inconsistent eye colour, generic-tabby substitution, excessive SVG complexity, muddy detail at documentation sizes, broken browser rendering, or anatomy that cannot be animated cleanly.

## Later Phases

After the static milestone is approved:

1. recreate the detailed Hero Waffle using the approved canon;
2. build a small animation controller around Motion Waffle's named SVG groups;
3. add idle, blink, sit, stand, walk, wave, think, success, warning, and sleepy states incrementally;
4. expose selected animations through the native Web Animations API, optionally using Motion for sequencing and spring ergonomics; and
5. reuse the same SVG groups for promotional videos, using Remotion while its licensing remains appropriate for the project or Blender as the free and open-source fallback.

This architecture deliberately avoids a required animation-editor subscription. The layered SVG remains the character source of truth; browser and video animation are code or scene derivatives rather than proprietary rig files. The tradeoff is that pivots, easing, and state transitions are authored in code instead of a visual rigging timeline.
